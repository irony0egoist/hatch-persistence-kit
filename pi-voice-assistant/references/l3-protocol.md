# L3 桥接协议：树莓派 ↔ Muse（Duckiji）

当用户问题超出本地技能和 Groq 快问答能力时（查价格、做攻略、实时信息、个人记忆、多步推理），
树莓派将其转交给 Muse 处理，Muse 用搜索/工具/记忆完成后再把答案送回音箱播报。

## 树莓派侧（发送）

意图分类为 `l3.ask` 时，`voice_chat.py` 执行：

```bash
musegadget send-user-msg "[PI-L3] <用户原话>"
```

同时做两件事：
1. 灯效：紫灯闪 3 次 → 常亮（表示等待中）
2. 语音先行播报："这个问题有点复杂，我让 Duckiji 查一下，查到就告诉你。"

## Muse 侧（处理）

在主聊天看到以 `[PI-L3]` 开头的消息时：

1. **用全部能力处理**：搜索、工具调用、用户记忆、多步推理。
2. **长答案发聊天**，音箱只播口语摘要。
3. **回树莓派播报**（SSH）：
   ```bash
   ~/stt/venv/bin/python ~/stt/speak.py "<100字内口语答案>"
   ```
4. 播报结束，树莓派侧灯效熄灭（`speak.py` 返回后 `wake_daemon` 继续监听）。

### 回答风格要求

- 口语化，100 字以内，适合语音播报
- 不要念 URL、不要报长串数字
- 结论先行，再补一句关键细节
- 示例：
  - 用户问"北京明天天气怎么样适合带宝宝出门吗" → "明天北京晴，最高18度，挺适合带宝宝出门的，记得带件薄外套。"
  - 用户问"帮我查下飞上海的便宜机票" → 长答案发聊天，音箱播："查到了，最便宜的是周四早上的春秋航空，480块，详情发你手机上了。"

### 超时与失败

- 如果 Muse 侧 2 分钟内无响应，用户可直接在手机上追问（L3 消息已在聊天里）。
- `musegadget send-user-msg` 发送失败时，树莓派播报"转交失败，你直接在手机上问我吧。"

## 消息格式

```
[PI-L3] <用户原话>
```

- 前缀固定为 `[PI-L3]`（注意是字母 PI，不是数字）。
- 后面直接跟用户说话的原文，不做改写（意图分类的 question 字段即原文）。
